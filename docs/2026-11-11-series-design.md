# 数学者のひらめき シリーズ 設計図

作成日：2026-11-11　／　状態：たたき台（承認待ち）

この文書は、いまの「ネイピアの閃き」（napier-log/index.html v1.4.0）を、中学・高校の単元ごとのシリーズに広げるための設計図です。これを読めば、作る人が持ち主に聞き返さずに計画を立てられることを目指しています。

「わたしの判断」と書いた所は、話し合いで決めたのではなく、設計を書いた側が決めた所です。持ち主が読んで、違えば直します。

---

## 1. 目的と、なぜ作るのか

- 中学・高校で**新しい単元に入る最初の授業**（導入）で使う。
- 公式や記号を「覚えるもの」ではなく、**困った人が、その場で思いついて名前をつけたもの**として体験させる。
- 生徒は現代の困りごとに直面し、歴史上の数学者と**一緒に考え**、自分の手で公式や記号を完成させ、問題を解決する。
- 最後に、その数学者の人柄がわかる話を読み、「数学者も人間なんだ」と親しみを持たせる。

## 2. 使い方

- 生徒が**1人1台**で、それぞれ自分のペースで遊ぶ。
- 端末は**タブレットかパソコン**。スマホは主な対象ではない（崩れない程度には動かす）。
- **1話5〜10分**。ネイピア編は10分くらいでよい。

## 3. ゴール・やらないこと・失敗とみなすこと

**ゴール**
- 1話を遊び終えた生徒が、その回の公式や記号を「なぜそうなるのか」とあわせて言える。
- 誤答を選んでも行き止まりにならず、ヒントで正解にたどり着ける。
- 話をあとから足しやすい（文章と設定を書き足せば、1話増やせる）。

**やらないこと**
- AIでの自由会話はしない（持ち主がA案「AIなし」を選んだ）。
- 生徒の名前や成績を集めたり、外部に送ったりしない。
- 長い説明文を読ませない。

**失敗とみなすこと（動いていても失敗）**
- 説明を読むだけで終わり、生徒が考える場面がない。
- 数学者が「答えを教える先生」になっている（一緒に考えて、その場で思いつく形にする）。
- 演出が怖い（ネイピアの線画は怖いと言われた）。
- 伝説を「本当」として表示するなど、歴史の誤り。
- 誤答を選ぶと先に進めなくなる。

## 4. 1話の流れ（全話共通）

ネイピア編 v1.4.0 の流れを土台にする。

| 順 | 場面 | 目安の時間 | 中身 |
|---|---|---|---|
| 1 | 現代の困りごと | 1分 | チャットで状況が進み、処理が止まる。左の写真は「困っている様子」 |
| 2 | 「どうする？」 | 0.5分 | 入力欄と自動入力ボタン（誤答入り）。どれを選んでも先へ進む |
| 3 | 数学者の登場 | 0.5分 | 左の写真の上に、数学者がホログラムで現れる |
| 4 | 一緒に気づく（体験） | 1.5〜2分 | 数える・動かす・試すなどの操作で、ひらめきの元に気づく |
| 5 | 名前をつける | 1分 | 数学者が「長くて言いにくいな」と困り、生徒の発言をきっかけにその場で名づける |
| 6 | 追加の問いかけ | 0〜1分 | 必要な話だけ（ネイピア編の「2 や 7 はどうなる？」など） |
| 7 | 公式を完成させるパズル | 1〜1.5分 | 空欄にブロックをはめる。試算で左右がそろうか確かめられる |
| 8 | なぜ速く・楽になるか | 0.5〜1分 | 古いやり方と新しいやり方を、具体的な数字で並べる |
| 9 | 解決と説明 | 1分 | 左の写真が「解決した様子」に変わる。仲間に「何をしたの？」と聞かれて説明する |
| 10 | 質問タイム | 自由 | 生徒が数学者に質問できる。「もう大丈夫です」で別れる |
| 11 | エピローグ | 1分 | 歴史、決めぜりふ、公式カード、人物ファイル |

- 5分に収めたい話では、6と8を省いてよい。
- 4の「体験」と7の「パズル」は、話ごとに中身が違う（5章を参照）。

## 5. 画面

**横向き（タブレット・パソコン。主な形）**
- 画面を左右半分に分ける。
- **左半分：現場の写真**。困っている写真で始まり、解決すると解決した写真に切り替わる。数学者のホログラムは、この写真の上に現れる。
- **右半分：いまの縦長チャット画面**（上に進み具合の表示、真ん中にチャット、下に操作パネル）。

**縦向き（タブレットを縦に持ったとき）**
- 上に写真を小さく（画面の高さの3割くらい）、その下にチャット。わたしの判断。

**色と雰囲気**
- いまと同じ、暗い背景と青い光の画面。
- 数学者は、持ち主が用意した写真風の画像を使う。ふちをぼかし、青い光をうすく重ねてホログラムに見せる（ネイピア編 v1.3.0 の方式）。
- 絵文字は使わない。アイコンは線のSVG。

**写真が届く前**
- 写真の場所に、何の写真が入るかを書いた仮の枠を出す。わたしの判断。

## 6. 会話の仕組み（AIなし）

ネイピア編 v1.4.0 の `talk()` / `STEP` / `FAQ` をそのまま使う。

- 入力欄は、**話をふられた場面だけ**出す。
- 入力欄の上に**自動入力ボタン**を2〜3個並べる。押すと文が1文字ずつ入力欄に打ち込まれ、送信で発言になる。自分で打ってもよい。
- ボタンには**わざと誤答を混ぜる**。誤答を送ると、理由とヒントが返ってきて、もう一度聞かれる。使ったボタンは消える。
- 自分で打った文は、言葉の決まりで答えを選ぶ。
  1. その場面の決まり（正答・誤答）
  2. どの場面でも使える「よくある質問」（話ごとの質問＋全話共通の質問）
  3. どれにも当たらなければ「それは難問だ。〇〇なら答えられるぞ」
- 正答の決まりは、誤答の決まりより後に調べる（「10 の 2 乗」が「乗」で正答扱いになる、といった取り違えを防ぐため）。

## 7. エピローグと人物ファイル

順番に表示する。

1. **ひらめきの歴史**：何年に、何を発表したか（2〜3行）
2. **決めぜりふ**：「数学のひらめきは、◯年後の世界も救っている」。年数は話ごとに計算する
3. **公式カード**：その回で完成させた公式と、ひと言の理由。ボーナスの公式を見つけていれば、それも出す
4. **人物ファイル**（持ち主と決定）
   - 顔写真（ホログラムと同じ画像から切り出す）
   - 名前、生まれた年と亡くなった年、国、肩書き
   - 面白いエピソード2つ。それぞれに「本当」か「伝説」の札をつける
   - 肖像が残っていない人物は「実際の顔はわかっていません」とひと言添える
5. ボタン：「別の話を選ぶ」「もう一度」

## 8. シリーズ全体の作り（わたしの判断。持ち主の確認が必要な点は12章）

- **タイトル画面 → 話の一覧 → 話**の3段にする。
- 話の一覧は学年ごとに並べ、カードに「学年・単元・数学者の顔・話の題」を出す。
- 遊び終えた話には「クリア」の印をつける。印は、その端末のブラウザの中だけに保存する（名前や成績は集めない）。
- 会話の速さを「ふつう／はやい」から選べるボタンを置く。2回目以降の生徒や、時間が足りない授業のため。
- 版番号は、シリーズ全体で1つ（タイトル画面の下に表示）。

## 9. 1話分のデータ（話を足すときに書くもの）

話ごとに、次の項目を1つのまとまりとして書く。共通の仕組みは触らずに、このまとまりを足せば1話増える形にする。

| 項目 | 中身 |
|---|---|
| 基本 | 学年、単元、話の題、ジャンル、版番号 |
| 数学者 | 名前、生没年、国、肩書き、画像、顔の切り出し位置、上半身の切り出し位置 |
| 写真 | 困っている写真、解決した写真、それぞれの説明文（仮の枠に出す） |
| 現場 | システム名、作業名、進み具合の止まる位置、状況の数字（例：完了予想）の出し方 |
| 導入の会話 | 仲間・システム・自分の発言の並び |
| 「どうする？」 | 自動入力ボタン（誤答入り）と返事 |
| 登場の言葉 | 数学者の最初のせりふ |
| 体験 | 体験パーツの種類と、その数字（5章の表を参照） |
| 名づけ | 問いかけ、自動入力ボタン（誤答入り）、正答・誤答の決まり、名づけのせりふ |
| 追加の問いかけ | 必要な話だけ |
| パズル | 式の形、空欄、使えるブロック、正解、ボーナスの組み合わせ、3回まちがえたときのヒント、試算に使う数 |
| なぜ楽になるか | 古いやり方と新しいやり方の行、ひと言のまとめ |
| 解決 | 完了メッセージ、仲間の言葉、結果の数字 |
| 説明の場面 | 自動入力ボタン（誤答入り）と返事 |
| 質問タイム | その話ならではの質問と答え（全話共通の質問に足す） |
| エピローグ | 歴史の文、決めぜりふの年数、公式カード、人物ファイル |

**体験パーツ**は、使い回せる形で次の3種類から始める。合わない話だけ、その話専用のパーツを作ってよい。

| 種類 | 中身 | 使う話 |
|---|---|---|
| タイルを数える | 数のタイルを並べたり、つなげたりして個数を数える | 対数、数列の和 |
| 数直線で動かす | 数直線の上で、右へ・左へ動かして位置を見る | 負の数 |
| 近づけて試す | 数を少しずつ変えて、目標に近づける | 平方根 |

## 10. 画像の取り扱い

- 数学者の画像も現場の写真も、**持ち主が別のAIで作って渡す**。こちらでは描かない。
- 必要になったら、人物名・使う場所・構図・プロンプトを添えて、持ち主に頼む。
- 写真は縦長 4:5、暗めの色、文字やロゴなし、中央の下を少し空ける。
- 画像は話ごとのフォルダに置く。ファイル名は「話の名前-crisis」「話の名前-solved」「話の名前-portrait」。

## 11. 最初に作る4話

### 11-1. ネイピア編の作り直し（高2・対数・宇宙）

- いまの v1.4.0 を、シリーズの形に合わせて作り直す。
- シチュエーションは**宇宙だけ**にする（スポーツと IT は外す）。
- 横画面の左右分割、写真の切り替え、人物ファイルを足す。
- 写真：管制室で頭を抱える技術者たち／打ち上げに歓声を上げる管制室。
- 人物ファイル：ジョン・ネイピア（1550〜1617、スコットランド、マーキストンの領主）
  - 伝説：使用人の中の泥棒を見つけるため、すすを塗った黒いニワトリを暗い部屋に置き、「さわれば泥棒がわかる」と言って一人ずつ入れた。手が汚れていない者が、怖くてさわらなかった犯人だった。
  - 本当：当時は数学より、聖書を研究して「世界の終わりの年」を計算した本で有名だった。

### 11-2. 負の数（中1・ブラーマグプタ・お店）

- **困りごと**：文化祭の焼きそばの模擬店。仕入れに 8,000円使ったのに、売上は 5,000円。帳簿の「もうけ」の欄に「5000 − 8000」が書けない。
- **体験（数直線で動かす）**：0円から、売上の分だけ右へ、仕入れの分だけ左へ動かす。すると、0 より左の 3000 の位置で止まる。
- **名づけ**：「0 より左にある数」を毎回そう呼ぶのは長い。生徒が「借りの数として、別の名前で呼んだら？」と発言し、ブラーマグプタが「財産を『正』、借りを『負』と呼ぼう」と名づける。
  - 誤答の例：「0 より小さい数なんてない」「8000 − 5000 にすればいい」（逆にすると、もうけか損かがわからなくなる、と返す）
- **パズル**：「売上 5000 − 仕入れ 8000 = [符号][数]」。符号（＋／−）と数（3000／13000）をはめる。
- **解決**：帳簿に「−3000（赤字）」と書け、いくら値上げすればよいかがわかる。
- **人物ファイル**：ブラーマグプタ（598ごろ〜668ごろ、インド、天文学者・数学者）
  - 本当：30歳ごろに書いた天文学の本で、数学の決まりを詩の形で書いた。
  - 本当：0 を「数」として扱い、0 ÷ 0 = 0 とまで考えた（今の数学では、この答えは正しくないとされる）。

### 11-3. 平方根（中3・ルドルフ・建築）

- **困りごと**：面積がちょうど 2㎡ の正方形の床をタイルで作りたい。一辺を 1.4m にすると 1.96㎡、1.5m だと 2.25㎡。いくら細かくしても、ぴったりにならない。
- **体験（近づけて試す）**：一辺の長さを 1.4 → 1.41 → 1.414 …と変えて2乗していくと、2 に近づくが、いつまでも終わらないことを体験する。
- **名づけ**：「2乗すると 2 になる数」と毎回言うのは長い。生徒が「記号で書けませんか？」と発言し、ルドルフが「根（radix）の r をくずした形で √ と書こう」と名づける。
  - 誤答の例：「1.414 と書けばいい」（それは近いだけで、ぴったりではない、と返す）、「2 の半分で 1 では？」（1 × 1 = 1 だ、と返す）
- **パズル**：「一辺 × 一辺 = 2 だから、一辺 = [?]」。ブロックは 1、2、√2、2²。試算で「√2 × √2 = 2」を確かめられる。
- **解決**：設計図に「一辺 √2 m（約 1.414m）」と書け、工場でぴったりに切ってもらえる。
- **人物ファイル**：クリストフ・ルドルフ（1499ごろ〜1545ごろ、ドイツ、計算の先生）
  - 本当：ドイツ語で書かれた最初の代数の本の一つ『Coss』（1525年）を書き、学者だけでなく商人にも読まれた。
  - 伝説：√2 が分数で表せないことを外にもらしたヒッパソス（古代ギリシャ）は、船から海に落とされた。
  - 実際の顔はわかっていない、と添える。

### 11-4. 数列の和（高2・数学B・ガウス・音楽ライブ）

- **困りごと**：ライブ会場のピラミッド型の客席。1列目は1席、2列目は2席…100列目は100席。合計の席数を1列ずつ足していて、開場に間に合わない。
- **体験（タイルを数える）**：1〜10 の階段の形を2つ用意し、片方を逆さにしてくっつけると長方形になる。各列が 11、それが 10 列で 110、その半分で 55。
- **名づけ**：この技をなんと呼ぶか、生徒と一緒に決める（例：「逆さにして足す」）。最後に、ガウスが「最初と最後を足して、個数をかけて、2 で割る」とまとめる。
  - 誤答の例：「平均の 50 に 100 をかける」（平均は 50.5 だ、と返す）、「100 × 100 ÷ 2 では？」（それだと 1 列分足りない、と返す）
- **パズル**：「S = n × ( a [?] l ) [?] 2」。正解は「＋」と「÷」。試算は n = 100、a = 1、l = 100。
- **解決**：合計 5,050 席が一瞬で出て、開場に間に合う。
- **人物ファイル**：カール・フリードリヒ・ガウス（1777〜1855、ドイツ、「数学の王」）
  - 本当：19歳で正十七角形のかき方を見つけ、数学の道に進むと決めた。
  - 本当：見失われた小惑星ケレスの位置を計算で予測し、再発見につなげた。
  - 話の中の「子どものころ、1 から 100 までの和を一瞬で出した」話は、言い伝えとして伝わっているもの。人物ファイルのエピソード2つとは別に、エピローグの歴史の文の中で「（言い伝え）」と添える。

## 13. 守ること

- ふつうの HTML・CSS・JavaScript だけで作り、外部のライブラリや、変換（ビルド）の手順は使わない。持ち主がファイルをそのまま GitHub に上げられるようにするため。わたしの判断。
- 画像は外のサイトから読み込まない。
- 1話作るたびに、次を確かめる。
  - 横向き（1280×800）と縦向き（800×1280）で、表示が崩れない。
  - すべての誤答ボタンを押しても、最後まで進める。
  - パズルの正解・ボーナス・3回まちがえたときのヒントが出る。
  - エラーが出ない。
- 台本の点検を、コードで自動でやる（各場面に正答のボタンがあるか、パズルの正解が使えるブロックで作れるか、など）。
- 版番号を上げる。

## 14. 作る人に任せること

- 体験パーツとパズルの細かい見た目や動き。
- 話ごとのせりふの細かい言い回し（7章の流れと、11章の中身を守る範囲で）。
- 「なぜ楽になるか」の表に出す具体的な数字。
- ファイルやフォルダの細かい分け方。

## 15. 配り方とフォルダ

1. **配り方（持ち主と決定）**：GitHub Pages の URL を生徒に配る。
   - シリーズを1つのフォルダにまとめ、画像は別ファイルで置く（HTML に埋め込まない）。
   - 一覧のページと、各話を直接開ける URL の両方を用意する（例：`…/hirameki/` と `…/hirameki/#napier`）。授業でその回の話だけ配れるようにするため。わたしの判断。
2. **シリーズの名前（わたしの判断、持ち主が変えてよい）**：「数学者のひらめき」。
3. **フォルダ（わたしの判断、持ち主が変えてよい）**：新しく `hirameki` フォルダを作り、GitHub 用もこの名前にする。いまの napier-log は作り直し前の版として残し、手を入れない。
